Инвентарь, магазины и торговля

Проект UI поверх готовых команд backend — Inventory (дарение, обмен, партийное хранилище) и Commerce (магазины, кошельки, резервы). Мокапы выдержаны в действующей теме characterLedger: пергамент, чернильный navy, бронзовый акцент, плоские карточки с рамкой.

01 · Информационная архитектура

Кампания становится якорем

Инвентарь и торговля существуют только внутри кампании. Монолитный CampaignsView разделяется: список кампаний и отдельная страница кампании с вкладками, от которой ветвятся новые разделы. Зелёным — новые маршруты.

08 · Попутные улучшения

Что подтянуть в текущем UI

Навигация

Страница кампании с вкладками

CampaignsView перегружен: создание, приглашения, роли, партии — в одной простыне. Список отдельно, кампания отдельно; торговле нужен этот якорь.

Обратная связь

Snackbar-хост и центр уведомлений

Сейчас ошибки только inline. Асинхронные события (подарок принят, резерв истёк) требуют глобальных снэкбаров и бейджей входящих.

Консистентность

Единый формат денег

Мастер создания показывает «120 cp» сырой медью. MoneyText (зм/см/мм) — везде, включая шаг Starting Equipment.

Код

Общие компоненты

CharacterCreateView — 2665 строк, DetailsView — 1186. Строки предметов, бюджет-алерт и bulk-сводка из шага 10 переиспользуются инвентарём — время выделить src/components/.

Производительность

Ленивые маршруты

Dynamic import для route-компонентов: бандл растёт с каждым большим view, торговля добавит ещё четыре.

Опционально

Тёмная тема characterLedger

Vuetify поддерживает пары тем; инверсия чернила/пергамент с теми же navy-teal-bronze акцентами.

09 · Этапность

Порядок внедрения

  1. «Посмотреть и передать». Read-проекции инвентаря и подарков → экран инвентаря → дарение → партийное хранилище. Самая быстрая ощутимая ценность.
  2. «Магазин». Проекции commerce → лавка игрока: покупка через резерв, продажа, кошелёк с журналом.
  3. «Сделки и админ». Стол обмена → панель ведущего → force-move → центр уведомлений с опросом.
