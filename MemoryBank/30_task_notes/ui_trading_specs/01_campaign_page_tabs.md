# ТЗ-01. Страница кампании с вкладками

Этап: MVP-1 (пререквизит остальных экранов). Сквозные требования — [00_overview_and_shared.md](00_overview_and_shared.md).

## Проблема

Весь функционал кампаний собран в одном `CampaignsView` (создание, приглашения, роли, партии, назначения). Новым разделам (хранилище, торговля, инвентарь) некуда встраиваться; у кампании нет собственного URL.

## Цель

Разделить: `/campaigns` — список, `/campaigns/:campaignId` — страница кампании с вкладками. Существующий функционал сохраняется без изменений поведения.

## Маршруты

| Путь | Название | Содержимое |
|---|---|---|
| `/campaigns` | `campaigns` | список кампаний + создание + мои приглашения |
| `/campaigns/:campaignId(\d+)` | `campaign-details` | вкладки: Обзор · Участники · Партия · Хранилище · Торговля |

- Вкладка — query `?tab=overview|members|party|storage|commerce` (deep-link, восстанавливается при F5).
- Несуществующая/недоступная кампания → редирект на `/campaigns` со снэкбаром об ошибке.

## Зависимости API

Только существующие: `GET/POST /api/campaigns`, endpoints `/api/campaign-membership/...`, `/api/campaign-parties/...`. Новых GET не требуется.

## Состав UI

### `/campaigns`

- Сетка карточек кампаний (существующий стиль dashboard-карточек): название, статус (активна/архив), моя роль (chip GameMaster/Player), число участников. Карточка целиком — ссылка на `campaign-details`.
- Форма создания и блок «Мои приглашения» — переносятся из текущего view как есть.

### `/campaigns/:campaignId`

- Шапка: eyebrow «Кампания», serif-название, chip роли текущего пользователя, для GM — кнопка «Архивировать» (существующий POST archive, с confirm-диалогом).
- `v-tabs` под шапкой:
  - **Обзор** — статус, роль, состав партии кратко, счётчики входящих операций (из `usePendingOperations`, появится в ТЗ-02 — до этого блок скрыт);
  - **Участники** — перенос существующего UI приглашений/ролей/членства;
  - **Партия** — перенос существующего UI партий и назначения персонажей; карточка назначенного персонажа — ссылка на campaign-карточку и кнопка «Инвентарь» (роут из ТЗ-02; до реализации — скрыта);
  - **Хранилище** — контент ТЗ-04 (до реализации — существующий placeholder-alert);
  - **Торговля** — список магазинов кампании (контент ТЗ-05); для GM — ссылка «Панель ведущего» (ТЗ-07); до реализации — placeholder «Магазины появятся здесь».
- Вкладки «Участники»/«Партия» видны всем участникам; действия внутри — по ролям (как сейчас).

## Сценарии

1. Пользователь открывает `/campaigns`, кликает карточку → `campaign-details?tab=overview`.
2. GM управляет приглашениями во вкладке «Участники» — поведение идентично текущему `CampaignsView`.
3. Переключение вкладки меняет query без перезагрузки; F5 возвращает ту же вкладку.
4. Игрок без членства открывает чужой URL → 403 от API → редирект на `/campaigns` + снэкбар «Нет доступа к кампании».

## Вне охвата

- Любая новая функциональность вкладок Хранилище/Торговля (отдельные ТЗ).
- Изменение API.

## Критерии приёмки

- [ ] Ни одна существующая операция (создание, приглашение, роль, партия, назначение) не потеряна и не изменила поведение; ручной прогон всех сценариев CampaignsView.
- [ ] Карточки списка — ссылки; прямой URL кампании и вкладки работает (deep-link, F5).
- [ ] Недоступная кампания не показывает частичный UI (редирект + снэкбар).
- [ ] Старый монолитный разметочный блок удалён из `CampaignsView` (не закомментирован).
- [ ] Роуты lazy; `meta.title` локализован ru/en.
