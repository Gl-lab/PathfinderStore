# ТЗ-07. Панель торговли ведущего

Этап: MVP-3. Мокап: секция 06. Сквозные требования — [00_overview_and_shared.md](00_overview_and_shared.md).

## Проблема

Все admin-команды Commerce (поселения, магазины, offer'ы, политики, кошельки) и force-move Inventory доступны только через API.

## Цель

Единая панель ведущего: `/campaigns/:campaignId/commerce-admin` (`commerce-admin`), вкладки Поселения · Магазин · Кошельки · Инструменты. Вход — ссылка во вкладке «Торговля» (видна только GM).

## Доступ

Только активный GameMaster кампании (роль из campaign-membership). Не-GM по прямому URL → редирект на страницу кампании + снэкбар. Сервер первичен (Forbid).

## Зависимости API

Существующие команды (`CommerceAdminController`, `PartyInventoryController`):
`POST settlements`, `POST settlements/{id}/shops`, `POST shops/{shopId}/catalog-offers`, `POST shops/{shopId}/stock-offers`, `POST shops/{shopId}/pricing-policy`, `POST wallets/{characterId}/adjustments`, `POST inventory/force-move`.

Требуемые:

| Endpoint | Назначение |
|---|---|
| `GET settlements` (из ТЗ-05) | дерево поселений/магазинов |
| `GET shops/{shopId}/offers?status=all` | ассортимент, включая скрытые |
| `GET wallets?campaignId=` | балансы всех персонажей кампании (список `WalletDto` без entries) + `GET wallets/{characterId}` с журналом |
| `GET /api/item-catalog/revisions?search=&scope=` | поиск опубликованных ревизий для catalog-offer |
| `GET .../inventory/containers?campaignId=` | контейнеры кампании (магазинные/партийные/личные) для stock-offer и force-move |
| Проекция инвентаря (ТЗ-02) в режиме GM | выбор предмета для force-move |

## Состав UI

### Вкладка «Поселения»

- Дерево: поселение → магазины (карточки, не таблица). Кнопки «+ Поселение», «+ Магазин» (внутри поселения) — диалоги с именем (+ описание, если поддерживает команда).
- Клик по магазину → вкладка «Магазин» с выбранным shopId (query `?shopId=`).

### Вкладка «Магазин» (селектор магазина в шапке вкладки)

- **Ассортимент:** таблица-карточка: offer (имя + chip `каталог`/`экземпляр`), цена (`MoneyText`), количество, `OperationStatusChip` статуса (активен/скрыт). Действия строки — если у backend есть команды изменения offer'а; **пока команд обновления нет** — строки read-only, создание только новых offer'ов.
- «+ Из каталога»: диалог — поиск по ревизиям ItemCatalog (autocomplete по `search`), затем `MoneyInput` цены за единицу и количество → `POST catalog-offers`.
- «+ Экземпляр»: диалог — выбор предмета из магазинного контейнера → цена → `POST stock-offers`.
- **Ценовая политика:** форма из полей команды pricing-policy (коэффициенты покупки/скупки), текущие значения из проекции; сохранение с confirm «повлияет на все цены магазина».

### Вкладка «Кошельки»

- Список персонажей кампании: имя, баланс, резерв (`MoneyText`), кнопка «±» → диалог корректировки: `MoneyInput` + знак (начислить/списать), **обязательное** поле «Описание» (валидация непустоты; текст попадает в журнал), предпросмотр «Баланс станет: X».
- Клик по персонажу — журнал кошелька (переиспользуется диалог журнала из ТЗ-02).

### Вкладка «Инструменты»

- Карточка «Принудительное перемещение» с предупреждением «Действие аудируется и видно игрокам». Кнопка danger «Force-move…» → диалог: персонаж/контейнер-источник → предмет → контейнер-назначение → **обязательная** причина → confirm с полным описанием перемещения.

## Сценарии

1. **Настройка с нуля:** поселение → магазин → политика → 2–3 offer'а → магазин виден игрокам во вкладке «Торговля» (проверка через второй аккаунт).
2. **Catalog-offer:** поиск «зель» → выбор ревизии → цена 4 зм, кол-во 12 → offer в списке, игрок может купить.
3. **Stock-offer:** предмет из контейнера магазина → в продаже единичный экземпляр.
4. **Корректировка кошелька:** +50 зм «награда за квест» → баланс игрока вырос, запись в журнале с описанием и автором.
5. **Force-move:** предмет из инвентаря игрока → в хранилище партии, причина «спорный лут» → предмет переместился, операция в аудите хранилища.
6. **Отказы:** списание больше баланса, цена ≤ 0, пустое описание/причина — валидация до запроса + серверные ошибки в alert.

## Состояния

- Нет поселений — empty-state с CTA «Создайте первое поселение».
- Магазин без offer'ов — подсказка «Прилавок пуст — добавьте товар из каталога или экземпляр».

## Критерии приёмки

- [ ] Не-GM не видит ссылку и получает редирект по прямому URL.
- [ ] Сценарий «настройка с нуля» проходит целиком; результат виден игроку.
- [ ] Корректировка без описания и force-move без причины невозможны (кнопка disabled + валидация).
- [ ] Все команды идемпотентны при повторном клике (`OperationId` в network-логе).
- [ ] Force-move оформлен как опасное действие (danger, confirm, предупреждение об аудите).
- [ ] Общие критерии из ТЗ-00.
