# ТЗ-04. Партийное хранилище (вкладка кампании)

Этап: MVP-1. Мокап: секция 03 (правая колонка). Сквозные требования — [00_overview_and_shared.md](00_overview_and_shared.md).

## Проблема

Корневое партийное хранилище существует в домене (deposit/withdraw по политике партии), во фронтенде — placeholder-alert в CampaignsView.

## Цель

Вкладка «Хранилище» страницы кампании (ТЗ-01): содержимое, вклад/изъятие, политика доступа, журнал.

## Зависимости API

Существующие: `POST .../inventory/party-storage/deposit|withdraw` (`CharacterId, ItemInstanceKey, ExpectedItemVersion, OperationId`).

Требуемые:

| Endpoint | Контракт (минимум) |
|---|---|
| `GET /api/campaigns/{cid}/inventory/party-storage` | `{ accessPolicy, items: [{ itemInstanceKey, version, quantity, revision: { name, primaryCategory, bulkTenths }, depositedBy: { characterId, name }, depositedAtUtc }], recentOperations: [{ kind, characterName, itemName, occurredAtUtc }] }` |

Открытый вопрос backend: команды настройки `accessPolicy` нет в web-слое (`Unconfigured` из CampaignManagement). Кнопка «Настроить политику» для GM появляется только вместе с командой — отдельная задача.

## Состав UI

1. Заголовок вкладки + chip политики: `Unconfigured` → chip error «политика не настроена» + tooltip «Операции могут отклоняться до настройки политики ведущим»; настроенная политика — chip обычный с локализованным названием.
2. Список предметов: `ItemListRow` (иконка, имя, стопка, bulk) + subtitle «положил {имя} · {давность}». Действие строки — «Взять» (tonal).
3. Кнопка «Положить из инвентаря…» (primary) — диалог: выбор персонажа (если у пользователя >1 в партии), затем список его предметов (переиспользуется листинг проекции ТЗ-02) с одиночным выбором → «Положить».
4. «Взять» — если персонажей >1, mini-select персонажа-получателя в confirm-диалоге; иначе сразу confirm.
5. Свёрнутый блок «Журнал» (`v-expansion-panel`): последние 10 операций из `recentOperations` («Варг положил Факел ×5 · вчера»).

## Сценарии

1. **Вклад:** диалог → предмет → «Положить» → 200: снэкбар, refetch хранилища и инвентаря персонажа.
2. **Изъятие:** «Взять» → confirm → 200: снэкбар «{предмет} у {персонаж}», refetch.
3. **Отказ политики:** 400 с доменным сообщением → alert в диалоге, локализованный текст «Политика партии запрещает…».
4. **Конфликт версии** (предмет успел уйти) — сквозное правило.
5. **Игрок без персонажа в партии:** действия скрыты, список read-only, подсказка «Назначьте персонажа в партию, чтобы пользоваться хранилищем».

## Состояния

- Пустое хранилище: empty-state «В хранилище пусто. Положите предмет из инвентаря».
- `Unconfigured` — работа не блокируется UI (сервер решает), но предупреждение видно всегда.

## Критерии приёмки

- [ ] Цикл deposit→withdraw двумя пользователями: предмет виден с корректным «кто положил», изъятие переносит его в инвентарь выбранного персонажа.
- [ ] Политика отображается; при `Unconfigured` предупреждение присутствует, фиктивной кнопки настройки нет.
- [ ] Журнал показывает последние операции после каждого действия.
- [ ] Двойные клики не создают дубли операций (идемпотентный `OperationId`).
- [ ] Общие критерии из ТЗ-00.
